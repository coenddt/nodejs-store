# nodejs-store 多 db 联合压力测试报告

日期：2026-09-12
脚本：[scripts/stress.js](../scripts/stress.js)（本仓库产品 = nodejs-store 宿主层）
运行方式：独立运行（与其他仓库压测脚本分时执行，表后缀 `js` 隔离数据）

## 1. 压测模型

四库并载（MongoDB / MySQL / PostgreSQL / SQLite），跨源 relation 联邦：

```
StressUser (Mongo) ──orders──> StressOrder (MySQL)   type: many
                  ──invoices─> StressInvoice (PG)    type: many
StressLog (SQLite) 独立写读
```

每 worker 每轮 5 操作（与 py-store/stress/stress.py 完全对称）：

| # | 操作 | 目标源 | 类型 |
|---|---|---|---|
| 1 | `queryFederated` 一条 GQL 跨 3 源拉嵌套 | Mongo+MySQL+PG | 联合读 |
| 2 | `insert(StressLog)` | SQLite | 写 |
| 3 | `count(StressInvoice)` | PostgreSQL | 读 |
| 4 | `query(StressUser)` 按名字过滤 | MongoDB | 读 |
| 5 | `update(StressOrder, $inc)` | MySQL | 写 |

负载：**8 workers × 200 rounds = 8000 次操作**。

## 2. 结果

| 指标 | 值 |

| 总操作数 | 8000 |

| 总耗时 | 12545 ms |
| **QPS** | **637.70** |

|---|---|---|---|---|
| 1600 | 27.83 ms | **25 ms** | 48 ms | 140 ms |

## 3. 与双宿主同跑（历史 8×200 轮）对比

| 指标 | 独立压测（本报告） | 双端同跑（历史） |
|---|---|---|
| QPS | 637.70 | 625.49 |
| 联邦 p50 | 25 ms | 26 ms |

独立压测吞吐小幅提升（+2%），说明 NodeJS 侧瓶颈主要在自身运行时（better-sqlite3 同步阻塞 + NAPI FFI 排队）而非双端数据库竞争。

## 4. 与 py-store 独立压测对比（同负载 8×200）

| 指标 | py-store | nodejs-store | 差距 |
|---|---|---|---|
| QPS | 824.35 | 637.70 | Python +29.3% |
| 联邦 p50 | 19.30 ms | 25 ms | Python 快 5.7 ms |
| max | 70.78 ms | 140 ms | Python 尾部低一半 |

## 5. 结论

1. **稳定性**：8000 次操作 0 错误，守卫功能（v1.1.0）在线无回归。
2. **正确性**：冒烟验证联邦嵌套结果形状正确。
3. **性能**：独立压测 638 QPS；尾部延迟（p95 33 / max 140 ms）仍显著高于 Python 侧。改进方向：SQLite 写改 worker 线程异步化、减少热路径 FFI 调用次数。

## 6. 复现

```powershell
$env:LOCAL_CORE='1'
node scripts/stress.js --workers 8 --rounds 200
```
