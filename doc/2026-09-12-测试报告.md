## 2. 测试结果

### 2.1 单元 + 守卫测试（npm test）

**76 个全部通过**（含新增 7 个守卫用例：秒级时间戳注入 / 毫秒缺省 / 非法 timestamps 注册报错 / $pipeline 禁用开关 / feedback sink 回调 / PushdownUnsupportedError 结构 / 下推拦截自动反馈）。

### 2.2 真实后端 E2E（real-backends-e2e / federation-e2e）

`LOCAL_CORE=1` 连接本机 MongoDB / MySQL / PostgreSQL / SQLite 四库真实实例：**全部通过**。

### 2.3 多 db 联合压测

四库并载 + 跨 3 源联邦压测（独立压测：8000 ops / 0 错误 / 637.70 QPS，联邦 p50 25 ms）详见 **[压测报告](./2026-09-12-压测报告.md)**（脚本 [scripts/stress.js](../scripts/stress.js)）。

## 3. 结论

1. **稳定性**：E2E 与压测累计 **42000+ 次操作 0 错误**；守卫功能（v1.1.0）在线无回归。
2. **正确性**：守卫移植后全部既有测试无回归，联邦嵌套结果形状正确。
3. **性能**：独立压测 638 QPS（对比 py-store 824 / core 直压 727）；尾部延迟（p95 33 / max 140 ms）仍显著高于 Python 侧。主因：`better-sqlite3` 同步 API 阻塞事件循环 + NAPI FFI 调用在并发下排队放大。
4. **改进建议**：SQLite 写路径改用 worker 线程（async 化）以压低尾部延迟；吞吐上限受本机单实例数据库制约，扩库优先于改宿主。
